## 카메라와 조명 — 세 과제가 같은 조건입니다

세 과제가 같은 로봇, 같은 매장에서 돕니다. **카메라와 조명은 모든 과제에 동일하게 설정되었습니다..**

**카메라 세 대.** 값은 실기 로봇(ROBOTIS ai_worker FFW-SG2)의 설정에서 가져와서 설정하였습니다.

| 카메라 | 크기 | 가로 화각 | 붙는 자리 | 그리는 거리 |
|---|---|---|---|---|
| `head_l` | 672×376 | 85.0° | `head_link2` 기준 (0.0238, 0.0250, −0.0110) | 0.1 ~ 100 m |
| `wrist_l` · `wrist_r` | 424×240 | 87.0° | `camera_l_link` · `camera_r_link` 원점 | 0.03 ~ 100 m |


**조명은 매장 씬이 들고 온 것을 그대로 씁니다.** 스크립트가 제 돔을 따로 켜지 않습니다.

| 조명 | 값 |
|---|---|
| 돔(DomeLight) | 850 · 흰색 |
| 태양(DistantLight) | 1500 · 흰색 |
| 냉장·냉동 진열장 안 RectLight 8개 | 각 15000 · 흰색 |

돔은 사방에서 고르게 드는 빛이라 그림자를 거의 만들지 않고, 태양은 한 방향에서 들어와
선반과 상품 밑에 그림자를 만듭니다.

## `task_a_demo.py` & `task_a_replay.py`

### 초기 환경 생성 (`task_a_demo.py`)

```bash
# 도커 컨테이너 내부에서 실행
cd /workspace/cyclo_lab
${ISAACLAB_PATH}/_isaac_sim/python.sh -u \
    /workspace/challenge_scripts/task_a_demo.py --seed 1000
```

시뮬레이션 창이 열리고 **과제 A 에피소드의 시작 환경**이 렌더된 상태로 대기합니다. 로봇은 추가적인 동작(집기, 주행, 놓기 등)을 수행하지 않고, 여러분들의 정책 모델이 받게 될 첫 번째 관측(Observation) 상태를  참여자분들이 직접 시각적으로 확인하기 위한 데모입니다.

### 시연 기록 재생(`task_a_replay.py`)

```bash
# 도커 컨테이너 내부에서 실행
cd /workspace/cyclo_lab
${ISAACLAB_PATH}/_isaac_sim/python.sh -u \
    /workspace/challenge_scripts/task_a_replay.py --seed 6
```

과제 A의 시작부터 끝까지 전체 시연 과정을 재생하는 스크립트입니다. 탁자에서 바구니를 집고 매장을 가로질러 목표 책상에 내려놓는 모든 과정이 포함되어 있습니다.

### 기구학(Kinematic) 기반 재생 방식 (Task A, B 공통)

재생 방식은 물리 엔진의 연산을 따르지 않고, 매 프레임마다 기록된 31개의 관절 각도, 베이스 좌표, 바구니의 자세 값을 **강제로 덮어쓰는 방식**으로 작동합니다.

*원본 기록은 GPU 기반의 물리 연산 및 컴플라이언트(Compliant) 바닥 환경에서 10 FPS로 수집되었습니다. 본 데모는 CPU 물리 연산 환경이므로, 긴 주행 시간 동안 누적되는 물리 연산 오차로 인한 바구니 떨어짐 현상을 방지하기 위해 강제 할당 방식을 채택했습니다.*

**재생 시 필수 검증 항목 (코드 자동 검사):**

1. **관절 이름 매핑:** 시연 기록의 관절 데이터(19개)와 베이스 휠(6개)을 실제 모델의 31개 관절 이름과 정확히 매핑합니다.
2. **그리퍼 동기화:** 2~4번 그리퍼 마디의 값을 1번 마디의 값으로 매 프레임 동기화하여, 허공을 쥐는 현상을 방지합니다.
3. **방향 기준축 변환:** 데이터를 수집한 환경과 현재 환경의 '위/아래 기준축'이 다른 것을 미리 방지하여, 이를 현재 환경 기준에 맞게 방향을 보정하여 로봇이 옆으로 눕거나 뒤집히지 않고 똑바로 서서 동작하게 합니다.

**물리 접촉 미구현:**
자세를 강제로 덮어쓰기 때문에, 그리퍼가 바구니를 누르거나 미끄러지는 등의 실제 물리적 마찰 및 상호작용은 렌더 화면에 표현되지 않습니다. (다만 3개의 시연 기록 모두 실제 환경에서 성공 검증을 마친 데이터입니다.)

## `task_b_demo.py` & `task_b_replay.py`

과제 B 환경은 특정 진열대 하나를 대상으로 진행됩니다.

### 초기 환경 생성 (`task_b_demo.py`)

지정된 5단 진열대에 상품이 채워지고, 2단과 3단의 앞줄 중 일부가 비워집니다. 빈 공간에 채워넣어야 할 상품은 책상 위 파란색 상자 안에 배치됩니다. 로봇은 상자를 마주 보고 정렬하며, 초기 시야에 진열대는 포함되지 않습니다.

**코드명 및 영문명 분리 관리:**
과제 B와 C의 상품은 시스템 내부적으로 처리하기 위한 **내부 코드명**(예: `pringles_original_small`)과 로봇 지시문에 사용되는 **표시용 영문명**(예: `small original Pringles tube`)으로 나뉘어 관리됩니다.

**Seed 및 빈 칸 조절:**

- `-gaps`: 진열대에 비워둘 칸의 개수 (1~3개, 기본값 1). 숫자가 늘어날수록 로봇이 수행해야 할 배치 작업 횟수가 증가합니다.
- `-seed`: 난수 시드 값. 동일한 gaps와 seed를 입력하면 항상 같은 상품과 위치가 생성됩니다.

### 시연 기록 재생 (`task_b_replay.py`)

사전 수집된 7개의 성공 시연 궤적을 재생합니다. 과제 A와 마찬가지로 물리가 아닌 기하학적 자세 덮어쓰기 방식으로 작동합니다.

- `-seed`: (0~6) 범위의 값을 입력하여 재생할 시연 기록을 선택합니다.
- 재생 중 15개 평가 항목(34점 만점)에 대한 실시간 채점 결과가 출력됩니다. 채점 로직 중 바닥에 상품이 떨어지면 그 즉시 해당 상품의 채점 프로세스가 중지됩니다.

## `task_c_demo.py` & `task_c_replay.py`

과제 C는 편의점 매장의 계산대를 배경으로 하며, 모바일 베이스 이동은 허용되지 않으며, 로봇은 계산대 앞 자리에 고정된 상태로 작업을 수행합니다.

### 초기 환경 생성 (`task_c_demo.py`)

계산대 상판 지정된 붉은색 띠 내부에 3개의 상품이 스폰됩니다. 스폰되는 상품은 설정된 물리 규칙(QR면 노출 방향, 최소 간격 유지, 원통 직립 등)을 준수하여 배치됩니다.

- `-seed`: 무작위 상품 3종과 배치 형태를 결정합니다. (**0, 1, 2번 시드**는 주최 측 평가 표본 데이터가 고정되어 있습니다.)
- `-products a,b,c`: 상품 3종을 수동으로 지정할 수 있으며, 첫 번째 상품이 로봇의 조작 대상이 됩니다. 위치는 시드에 의해 자동 결정됩니다.

상품 사이 표면 간격 **8 cm** 는 필수 조건입니다. 재배치를 다 써도 지키지 못하면 장면을 만들지 않고 실패로 끝냅니다. 상품이 놓일 띠 안쪽이 26 × 55 cm 라, 8 cm 면 8 종 중 3 종을 고르는 56 개 조합이 모두 놓입니다(2026-09-12 실측).

### 시연 기록 물리 재생 (`task_c_replay.py`)

과제 C의 시연 재생은 과제 A, B와 달리 **물리 엔진 기반 재생 방식**을 사용합니다. 기록된 관절 명령(actions)을 로봇에게 프레임별로 인가하고, 시뮬레이터 내부의 물리 엔진이 상품과의 상호작용 및 움직임을 직접 연산합니다.

물리로 다시 도는 방식이라 기록과 똑같이 재생되지는 않습니다. 접촉과 마찰을 매 스텝 새로 계산하므로, 손에 닿는 순간의 작은 차이가 뒤로 갈수록 벌어집니다. 동봉된 판과 허깅페이스 데이터 모두 수집 당시와 같은 결과를 보증하지 않습니다.

- `--set gt`: 3개의 상품을 연속 처리하는 정답 궤적 재생 (2편, `--seed 0~1` — GT0 은 3개 모두 성공 51/51, GT1 은 사워크림 1개 실패 38/51)
- `--set single`: 상품 1개를 처리하는 훈련 데이터 형식 재생 (4편, `--seed 0~3`)
- `--lerobot DIR --episode-index N`: 허깅페이스 LeRobot 데이터셋의 한 편을 재생
- `--trace DIR`: 채점에 쓸 관측치를 프레임마다 기록

채점은 재생과 분리되어 있습니다. `--trace` 로 남긴 기록을 `scorer/score_from_trace.py` 가 채점하고, `scorer/check_trace.py` 가 기록과 채점 결과의 모순 여부를 검사합니다. 상품 1개당 5개 항목 17점, 계산대 위 3개를 처리하므로 51점 만점입니다. 자체 검증 모듈은 `scorer/selftest.py` 이며, 절차와 판정 기준은 `docs/task_c.md` 6절에 있습니다.
