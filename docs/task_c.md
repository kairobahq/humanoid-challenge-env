> [← 메인 README 로 돌아가기](../README.md)

다음 명령어를 통해 Task C의 초기 씬을 확인할 수 있습니다.

```bash
cd /workspace/cyclo_lab
```

들어가기 앞서 task-C의 경우 스캐너 인식과 점수 연동, 스캐너 빔 점군 생성등의 이유로 다른 테스크에 비해 환경이 약간 더 무겁습니다. 참가자분들께서는 참고부탁드립니다.

### 1. 환경 주요 요소

* **매장 및 계산대:** 과제 A와 동일한 편의점 전체가 생성되며, 실제 작업은 매장 남서쪽에 위치한 **계산대** 앞에서 진행됩니다. 과제 C는 모바일 베이스가 계산대 앞 자리에 고정된 상태로 수행하며, 모바일 베이스 이동은 허용되지 않습니다(동봉된 시연도 모두 제자리에서 수행).
* **빨간 띠 (계산대 상판):** 상판(높이 0.9035 m) 위 로봇 기준 전방 30~60 cm · 좌측 -2~57 cm 를 폭 20 mm 테이프로 두른 자리입니다. **상품은 이 안에서만 스폰됩니다.** 테이프 폭을 뺀 안쪽은 26 × 55 cm 입니다.
* **상품 3개:** 8종 중 시드가 고른 3개가 띠 안에 놓입니다. **슬롯 0 이 집어야 할 목표 상품**이고 나머지 둘은 배경입니다. 셋 다 **QR 면이 로봇 기준 우측(월드 -Y)을 향하고**, 원통형은 세워서·상자형은 눕혀서 놓이며 **상품 표면끼리 최소 8 cm** 를 띄웁니다.
* **스캐너:** 로봇의 오른손에 들려 있습니다. 계산대에 붙박인 집기가 아니라 오른팔이 가는 곳으로 따라가고, 손목을 비틀면 겨눔도 같이 돌아갑니다. 떨어지지 않도록 중력은 걸지 않습니다. 상품은 왼손으로 집어 이 스캐너에 QR코드를 인식시키는 것이 과제의 핵심입니다.
* **로봇:** 계산대를 정면으로 마주 본 상태로 대기합니다. 리프트 0.0 m, 고개 45° 숙임, 양팔 스토우(Stow) 자세를 유지하며 바퀴는 바닥에 밀착되어 있습니다.
* **로봇 설정:** 과제 A·B 가 쓰는 공용 `FFW_SG2.py` 대신 **학습 데이터 수집 당시의 설정** `scripts/taskC/taskC_ffw_sg2.py` 로 로봇을 세웁니다(강성·감쇠·그리퍼 마찰이 다릅니다). 재생기가 관절 명령을 물리로 다시 돌리므로 이 설정이어야 파지·스윕이 나오며, 정책 평가도 같은 설정으로 합니다.
* **관측 카메라:** 시각 데이터 카메라는 머리 장착 `head_cam` (672×376, ZED 좌안) 1대와 양 손목 `left_wrist_cam`, `right_wrist_cam` (424×240, D405) 2대로 과제 A·B와 유사합니다.

### 3. 환경 생성 파라미터 (`--seed`, `--products`)

생성되는 씬의 형태는 기본적으로 `--seed` 옵션 하나로 모두 결정됩니다. (상품 3종의 종류, 띠 내 배치 위치, 자세 등)

* **`--seed` (환경 시드):** 고유 장면 번호입니다. 모든 시드가 같은 방식으로 배치(딜)됩니다. 정답 궤적(`--set gt`)은 새 구성으로 다시 수집하는 중이라 이번 배포에는 빠져 있습니다. 준비되는 대로 올리겠습니다. 다시 실을 때 시드 0·1·2 를 그 장면에 묶어 두겠습니다.
* **`--scene-file` (장면 파일 지정):** 무작위 배치를 하지 않고 제공된 장면 JSON 파일(`--scene-json` 출력 또는 동봉 기록의 `taskC_qr_scene_*.json`)에 기록된 상품 자세를 그대로 로드합니다. 정답 궤적 재생 및 채점 로직 검증 시 사용합니다.
* **`--products` (상품 강제 지정):** 코드 식별자 3개를 쉼표로 연결하여 전달하면 시드가 결정하는 상품 대신 해당 상품 3개를 강제로 사용합니다. **첫 번째 식별자가 목표 상품이 됩니다.** (예: `--products cocacola_zero,lotte_sand,yegam_original`)
* *참고:* 스폰 뒤 3초간 물리로 정착시키고, 띠 밖으로 밀리거나 넘어지거나 QR 방위가 3° 넘게 틀어지거나 간격이 8 cm 미만이면 같은 시드 안에서 최대 50회 재배치합니다. 출력 좌표는 **정착 후 실측값**입니다.
* *재배치를 다 써도 규칙을 못 지키면 장면을 만들지 않고 실패로 끝냅니다.* 표면 간격 8 cm 는 필수 조건이라, 어긴 배치를 내보내지 않습니다.
* **간격 8 cm 의 근거:** 상품이 놓일 띠 안쪽은 26 × 55 cm 입니다. 여기에 상품 3 개를 서로 떼어 놓아야 하는데, 더 넓게 잡으면 **예감(긴 변 21 cm)과 컵라면 2종(삼양 불닭컵 · 오뚜기 컵누들 불닭)이 한꺼번에 나오는 조합**처럼 자리가 아예 안 나오는 경우가 생깁니다. 8 cm 면 8 종 중 3 종을 고르는 **56 개 조합이 모두** 놓입니다(2026-09-12 실측 224/224).

### 4. Headless 모드를 활용한 빠른 데이터 추출

```bash
${ISAACLAB_PATH}/_isaac_sim/python.sh -u \
    /workspace/challenge_scripts/task_c_demo.py --seed 1000 --headless --seconds 1 \
    --scene-json /workspace/user/scene_c_1000.json \
    --shot /workspace/user/shot_c_1000.png
```

* **`--scene-json`:** 상품 3개의 상세 정보(월드/로봇 기준 좌표, 자세), 빨간 띠 위치, 로봇 시작 자세, 스캐너 위치, 카메라 해상도가 저장됩니다.
* **`--shot`:** 씬 생성 직후 `head_cam` 시점을 PNG로 캡처합니다.
* **`--check`:** 렌더링 구동 없이 1초 만에 상품 8종의 USD 및 QR 타일 정보, 스캐너, 매장 USD 정상 로드 여부와 빨간 띠 기하 구조를 검증합니다. 오류 발견 시 `!`로 시작하는 경고 로그를 출력하고 강제 종료(Exit code 1)합니다.

### 5. Task C 데모 시연 재생 (Replay)

`task_c_demo.py`가 정지된 장면을 띄운다면, `task_c_replay.py`는 로봇이 계산대의 상품을 집어 스캐너에 비추고 다시 내려놓는 시연 과정을 보여줍니다. 2가지 묶음으로 총 7개의 시연 데이터가 제공됩니다.

| 데이터 묶음 | 내용 | 편수 | 파일 위치 |
| --- | --- | --- | --- |
| **`--set gt`** | 실제 평가 기준과 동일 형식 — **잡기 → QR 인식 → 내려놓기**를 계산대 위 **상품 3개에 대해 연속 3번** 수행하는 정답 궤적 | 2편 (`--seed 0~1`) | `scripts/taskC/demos_gt/` |
| **`--set single`** | 모델 학습 데이터 형식 — **잡기 → QR 인식 → 내려놓기**를 **상품 1개에 대해 1번만** 수행 | 4편 (`--seed 0~3`) | `scripts/taskC/demos/` |

```bash
cd /workspace/cyclo_lab
${ISAACLAB_PATH}/_isaac_sim/python.sh -u \
    /workspace/challenge_scripts/task_c_replay.py --set single --seed 0
```

과제 A·B 재생기가 좌표를 덮어씌우는 것과 달리, 과제 C 재생기는 **기록된 관절 명령(`actions.npy`, 22채널, 30 Hz)을 같은 주기로 로봇에 인가해 물리가 상품을 움직이게 합니다.** 기록에 상품의 절대 좌표가 없기 때문입니다. 그래서 파지가 미끄러지는지도 이 화면이 답할 수 있습니다.

한 에피소드는 상품마다 8국면(접근 · 파지 · 들어 올림 · 스캔 2회 · 내려놓기 · 후퇴 · 복귀)입니다. 끝나면 상품별 최대 들림, 스캐너 최근접 거리, 최종 배치를 출력하고 `--summary-json` 으로 저장합니다.

#### 허깅페이스 학습 데이터 직접 재생

동봉된 6편 말고, 주최 측이 공개한 학습 데이터 1,089편도 틀 수 있습니다.

**다만 기록과 똑같이 재생되지는 않습니다.** 접촉과 마찰을 매 스텝 새로 계산하므로 손에 닿는
순간의 작은 차이가 뒤로 갈수록 벌어져, 편에 따라 상품을 놓치거나 QR 을 못 읽습니다. 로봇이
어떤 순서로 무엇을 하는지 보는 용도로 쓰시기 바랍니다.

> https://huggingface.co/datasets/SSU-RealityLab/2026CS-Store-Challenge

```bash
cd /workspace/cyclo_lab
${ISAACLAB_PATH}/_isaac_sim/python.sh -u     /workspace/challenge_scripts/task_c_replay.py     --lerobot /path/to/2026CS-Store-Challenge --episode-index 792
```

편 번호는 데이터셋의 `meta/taskC_episodes.jsonl` 에 있는 `episode_index` 입니다. 그 파일이
편마다 상품·바코드·등급과 함께 **장면 시드(`seed`)** 를 알려 줍니다.

**장면은 데이터셋이 아니라 이 저장소가 싣습니다.** 1,089편의 계산대 배치가
`scripts/taskC/scenes/<시드>.json` 에 있고, 재생기가 위 `seed` 로 짝을 찾아 장면을 세운 뒤
parquet 에서 관절 기록을 꺼내 `scripts/taskC/.lerobot_cache/` 에 펼쳐 재생합니다.
parquet 을 읽으므로 시뮬레이터 쪽 파이썬에 `pyarrow` 가 필요합니다
(`${ISAACLAB_PATH}/_isaac_sim/python.sh -m pip install pyarrow`). GUI 로 보려면
`run/run_task_c_replay.sh` 의 `LEROBOT` · `EPISODE_INDEX` 를 채우되, 경로는 컨테이너 안
기준이어야 합니다. 동봉된 6편은 LeRobot 형식이 아니라 폴더 형식이므로 `--set` 으로 틉니다.

#### 동봉된 데모 데이터 상세 (정답 궤적 2편 · 싱글 4편)

싱글 4편은 수집 파이프라인에서 성공 판정(QR 인식 1회 이상, 띠 안 배치)을 받은 것 중 이 재생기에서
QR 인식까지 되는 것만 골라 실었습니다. 정답 궤적 2편은 아래 표대로이며, GT1 은 상품 하나가
실패한 판을 부분 점수 예시로 그대로 실었습니다. 들림은 상품이 상판에서 떠오른 최대 높이입니다.

#### 정답 궤적 2편 (`--set gt`)

정답 궤적은 같은 장면(시드)에서 상품 3개를 **잡기 → QR 인식 → 내려놓기** 순으로 연속 수행한
한 편입니다. 상품마다 8국면(`s0_approach` … `s0_ret_retreat`)이 있고, 상품 사이에 기본자세
복귀 국면(`gt_home`, 2초 등속 + 1초 정지)이 들어갑니다. `meta.json` 의 `chain_order` 가 상품
순서이고, `phases.json` 의 국면 이름 앞 `s<슬롯>` 이 재생기가 빔·판독 대상을 바꾸는 표식입니다.

만든 방법: 수집 파이프라인으로 같은 시드에서 상품 3개를 각각 기록(단독 판)한 뒤 관절 기록을
이어 붙였습니다. 그래서 **이 재생기로 틀어야 연속 한 장면**이 됩니다(앞 상품을 내려놓은 자리가
그대로 남습니다). 동봉된 `initial_cam_*.jpg` 는 첫 프레임 한 장뿐이며, 연속 영상이 필요하면
`--record DIR` 로 재생하며 적으십시오. 참고용으로 그렇게 찍은 영상을 각 폴더에 함께 두었습니다
(`dev_replay_<채점>of51.mp4`: 머리캠·왼손목캠·오른손목캠 나란히, 하단에 프레임·국면 표시).

아래는 이 재생기(`--trace`)로 연속 재생해 잰 값입니다. 들림은 상품이 상판에서 떠오른 최대
높이, 판독은 스캐너 카메라 이미지로 QR 이 읽힌 횟수입니다.

| `--set gt --seed` | 시드 | 상품 순서 | 결과 |
| --- | --- | --- | --- |
| **0** (GT0) | 6601333000 | 프링글스 사워크림 → 롯데샌드 → 예감 | **상품 3개 모두 성공** — 슬롯0 들림 337mm·판독 2회 / 슬롯1 433mm·판독 2회 / 슬롯2 405mm·판독 4회. 예감은 띠 테두리에 걸쳐 놓입니다(밖으로 나가지 않음, 득점 인정) |
| **1** (GT1) | 6401288000 | 롯데샌드 → 프링글스 사워크림 → 예감 | **2개 성공 · 1개 실패** — 슬롯0 416mm·판독 2회 / **슬롯1 사워크림 헛집음(들림 24mm·판독 0·띠 밖)** / 슬롯2 387mm·판독 3회. 부분 점수 예시 |

GT1 의 슬롯 1 은 같은 판을 단독으로 틀면 잡힙니다(들림 309mm). 앞 상품(롯데샌드)이 내려놓인
자리가 원위치에서 약 25mm 어긋난 채 남은 장면에서 이어 틀 때만 헛집습니다 — 연속 3번 수행이
단독 수행과 다른 점을 보여 주는 예시로 그대로 실었습니다.

GT0 의 예감 구간에서는 예감을 잡으러 들어가는 손이 옆 사워크림을 66mm 밀어냅니다(연속 재생
실측). 이미 처리한 상품이라 판독·배치 결과는 위 표대로이며, 사실로 적어 둡니다.


싱글 4편은 모두 상품을 들어 스캐너에 대고 QR 을 읽힌 뒤 띠 안 제자리로 되돌립니다.

| **0** | 코카콜라 제로 캔 (`cocacola_zero`) |

싱글 4편의 편별 프레임 수·최대 들림·QR 인식 횟수는 비워 두었습니다. 재생기가 판이 끝날 때 이 값들을

### 6. Task C 채점기 (Standalone)

과제 C의 평가 기준(상품 1개당 5개 항목, 총 17점: 파지 2점 · 들어 올림 2점 · 스캐너 조준 3점 · QR 인식 7점 · 띠 배치 3점 — 상품이 띠에 **일부라도 겹치면(걸쳐 있어도)** 인정)이 반영된 채점 코드가 `scripts/taskC/scorer/` 디렉토리에 제공됩니다. 시뮬레이션 루프 내에서 매 스텝 관측치를 받아 판정하며(`taskc_scorer.py`), Isaac Sim 없이 Numpy만으로 동작하는 자체 검증 모듈이 포함되어 있습니다.

```bash
python3 scripts/taskC/scorer/selftest.py      # 기하학적 수치, 시나리오, 규정 준수 등 35개 테스트 수행
```
항목별 임계값은 `taskc_scorer.py`의 `ScoreConfig`에 있습니다. 제한 시간과 총점 표기는 아직 확정되지 않았습니다.

#### 재생 결과를 채점하기

재생기에 `--trace`를 주면 채점에 필요한 관측치를 프레임마다 기록합니다. 기록된 것을 나중에 채점하므로 채점 규칙을 고칠 때 재생을 다시 돌릴 필요가 없습니다.

```bash
# 1) 재생하며 관측치를 남깁니다 (--q-free-close 는 빈손 닫힘 위치, 아래 설명 참조)
python3 scripts/task_c_replay.py --set single --seed 1 --headless     --trace out/trace --q-free-close 1.100021

# 2) 채점합니다
python3 scripts/taskC/scorer/score_from_trace.py     out/trace/trace.jsonl out/trace/scene.json out/trace/decode.json out/score.json

# 3) 기록과 채점 결과가 서로 모순되지 않는지 자동 검사합니다
python3 scripts/taskC/scorer/check_trace.py out/trace
```

`--q-free-close`는 빈손으로 그리퍼를 끝까지 닫았을 때 관절이 서는 위치이고, 파지 판정이 헛집기를 거르는 데 씁니다. `--measure-q-free`로 한 번 재면 계속 씁니다 — 재는 동안 그리퍼를 열어야 하므로 채점할 판 안에서 재면 안 됩니다. 또한 파지(Sub1-1)는 부하가 걸린 채로 상품이 상판에서 5 mm 이상 떠 있는 상태가 0.5초 이상 연속돼야 인정됩니다(2026-09-16). 옆면을 누르거나 닿기만 한 접촉, 쳐서 잠깐 들린 것은 부하가 걸려도 0점입니다.

#### QR 판독은 스캐너 카메라 이미지로 합니다

기하로 겨눔만 맞으면 되는 것이 아니라, 스캐너 시점 렌더 프레임을 zxing으로 디코드해 그 상품의 코드 문자열이 실제로 읽혀야 인정합니다. 매 프레임 렌더하지 않고 세 단계로 나눕니다.

| 단계 | 동작 |
|---|---|
| 판독 창 | 빔 축에서 횡이탈 60 mm 이내, 빔 출발선에서 축거리 40~150 mm, 타일 면각 30도 이내, 스캐너 화각 반각 18도 이내에 들어오면 디코드를 시도합니다 (`TASKC_QR_LAT_MAX` · `TASKC_QR_DMIN_MM` · `TASKC_QR_DMAX_MM` · `TASKC_QR_FACE_MAX` · `TASKC_QR_CONE_HALF` 로 조정) |
| 이미지 판독 | 창에 들어온 그 프레임만 스캐너 카메라를 렌더해 디코드합니다 |
| 냉각 | 한 번 읽히면 5초 동안 판독기를 끕니다. 창을 벗어나도 끕니다 |

창은 「디코드를 시도해도 되는 자리」를 정할 뿐이고, 판독 성립은 기대 바코드가 실제로 읽혀야 합니다. 그래서 창을 넓혀도 거짓 판독은 생기지 않고 시도 기회만 늘어납니다. 수집 당시 실측 창은 횡이탈 40 mm · 축거리 50~150 mm · 면각 12도였는데(동봉된 학습 데이터의 판독은 횡이탈 35~38 mm 에서 일어났습니다), 학습된 정책이 상품을 스캐너 앞 7 cm 까지 가져오고도 면각이 12도를 넘어 한 번도 시도하지 못하는 일이 있어 2026-09-16 에 횡이탈 60 mm · 축거리 40~150 mm · 면각 30도로 넓혔습니다. 축거리 상한 150 mm 는 평가 기준의 「빔 출발선에서 15 cm」와 같고, 화각 반각 18도는 스캐너 카메라의 화각이라 그대로입니다. 빔 자국·LED·띠 점등을 켜는 시각 판정은 종전대로 횡이탈 40 mm 를 쓰므로, 점등 없이 판독만 성립하는 자리(횡이탈 40~60 mm)가 있을 수 있습니다. 판독이 되면 LED 는 어느 자리에서든 3회 깜빡입니다.

`TASKC_QR_IMG=0`으로 끄면 기하 판정만 남고, 어느 쪽으로 판정했는지는 `decode.json`의 `by` 필드에 남습니다.
