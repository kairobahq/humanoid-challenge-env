# 🤖 실기 로봇 카메라 오차 시뮬레이션 가이드 (`--zed-depth` 옵션)

시뮬레이션 속 로봇은 사물의 거리(Depth)를 100% 정확하게 인식하지만, **실제 로봇 카메라(ZED Mini)는 여러 가지 환경적 요인 때문에 거리 인식에 오차가 발생합니다.**

이 문서는 시뮬레이션 환경에서도 실제 로봇과 비슷하게 카메라 오차를 일부러 발생시켜서 미리 테스트해 볼 수 있는 기능(`--zed-depth`)에 대해 설명합니다. (참고로 이 기능은 테스트/분석용이며 과제 평가에는 영향을 주지 않습니다.)

### 💡 용어 정리

* **정답 depth**: 시뮬레이션이 알려주는 100% 정확한 실제 거리.
* **ZED depth**: 시뮬레이션 화면을 실제 카메라 시스템(ZED SDK)에 통과시켜서 얻어낸 '현실적인(오차가 포함된)' 거리.

---

## 1. 실제 로봇 카메라에서는 어떤 오차가 생기나요?

최근 공지(26.10.05)된 실제 로봇의 거리 인식 오차는 크게 3가지입니다.

1. 표면에 무늬가 있는 물체는 실제보다 **1–2cm 더 멀리 있는 것**으로 인식됩니다.
2. 무늬가 없는 넓은 면(흰 판, 파란 바구니 바닥 등)은 멀리 있을수록 **위로 휘어지는 것처럼 왜곡**됩니다.
3. 물체의 가장자리 부분은 배경과 거리가 섞여서 **1–2cm 두께로 뭉개집니다.**

## 2. 이 옵션을 켜면 시뮬레이션에 어떤 효과가 추가되나요?

위와 같은 현실적인 오차를 재현하기 위해 `--zed-depth` 옵션을 켜면 시뮬레이션에 다음 효과들이 들어갑니다.

* **듀얼 카메라 모사**: 로봇 머리에 실제 카메라처럼 63mm 간격으로 렌즈 두 개를 달아 촬영한 뒤, 이 두 이미지를 실제 ZED SDK에 넣어 거리를 계산합니다.
* **물리적 렌즈 효과**: 카메라 모서리가 어두워지고(비네팅), 렌즈가 살짝 흐려지며, 빛의 밝기에 따라 센서 노이즈가 낍니다.
* **변덕스러운 매장 조명**: 실행할 때마다 매장 조명의 밝기(1.5–3배)와 색온도(3500–6500 K, 따뜻한 빛–차가운 빛)가 랜덤하게 바뀝니다.
* **거리 왜곡(캘리브레이션 오차)**: 실기 공지의 1–2% 와 비슷하게, 물체가 약 1.5% 더 멀리 인식되도록 일부러 오차를 넣었습니다.

---

## 3. 실행 준비하기 (Docker 세팅)

이 기능을 쓰려면 거리를 계산해 줄 별도의 ZED SDK 컨테이너(`zed_depth`)를 띄워야 합니다.

**요구 사양**

* NVIDIA 드라이버 버전 570 이상 (CUDA 12.8 사용)
* 여유 GPU 메모리 약 2.4GB
* 여유 디스크 약 20GB (ZED SDK 이미지)

**실행 명령어**

```bash
cd docker
docker compose -f docker-compose.yaml -f zed.yaml up -d
docker logs -f zed_depth
```

> **⏳ 주의:** 처음 실행할 때는 시간이 더 걸립니다. 약 20GB 이미지를 받아 새로 만들고(네트워크에 따라 걸리는 시간이 다릅니다), 그다음 AI 모델을 GPU에 최적화하느라 몇 분이 더 걸립니다. 로그에 **"127.0.0.1:7300 에서 기다립니다"** 라고 뜨면 준비가 끝난 것입니다. (두 번째부터는 바로 켜집니다.)

---

## 4. 실행하는 방법

준비가 끝났다면 제공된 쉘 스크립트로 편하게 실행할 수 있습니다.

```bash
./run/run_zed_depth.sh b 0          # 과제 B의 0번(0~6) 시연 실행
./run/run_zed_depth.sh a            # 과제 A 기본 시연 실행
./run/run_zed_depth.sh c 0          # 과제 C의 0번 시연 실행
```

이 스크립트를 실행하면 화면 없이(headless) 재생기(Replay)가 돌아갑니다. ZED SDK가 프레임마다 거리를 계산하기 때문에 처리 시간이 꽤 걸립니다. (프레임당 약 0.4초, 과제 B 시연 하나당 8–19분 소요)

## 5. 결과 확인하기

실행이 끝나면 `workspace/zed_depth/<과제_시연>/` 폴더에 결과물이 나옵니다.

가장 먼저 확인해 볼 파일은 **`compare.mp4`** 입니다. 화면을 4분할하여 원본 이미지, 정답 거리, ZED 인식 거리, 그리고 두 거리의 '차이(오차)'를 한눈에 볼 수 있는 영상입니다. (파란색은 ZED가 더 가깝게, 빨간색은 더 멀게 인식한 곳입니다.)

그 외에도 프레임별 원본 이미지 파일(`head_l/`, `raw_l/`), 거리 데이터 파일(`depth_zed/`, `depth_sim/`), 통계 파일(`stats.csv`, `summary.json`)이 남습니다.

여러 번 테스트한 결과를 한 표로 모아서 보고 싶다면 아래 파이썬 스크립트를 돌리시면 됩니다.

```bash
${ISAACLAB_PATH}/_isaac_sim/python.sh /workspace/challenge_scripts/zed_depth/zed_summary.py /workspace/user/zed_depth
```

## 6. 추가 옵션 설명

아래 옵션은 실행 스크립트 뒤에 붙이면 됩니다. 과제 A 는 옵션을 붙일 때 시연 번호(기본 6번)도 함께 적어 주세요.

```bash
./run/run_zed_depth.sh b 0 --zed-every 2
./run/run_zed_depth.sh a 6 --zed-every 2
```

| 옵션 | 설명 |
| --- | --- |
| `--zed-every N` | N번째 프레임마다 한 번씩만 계산합니다. (시간 단축용) |
| `--zed-frames N` | 처음 N개의 프레임까지만 계산하고 멈춥니다. |
| `--zed-no-sensor` | 렌즈 흐림이나 노이즈 같은 센서 효과를 끕니다. |
| `--zed-no-video` | `compare.mp4` 비교 영상을 만들지 않습니다. |
| `--light-scale LO HI` / `--light-temp LO HI` | 랜덤으로 고를 조명 밝기(기본 1.5–3배)와 색온도(기본 3500–6500 K)의 범위를 정합니다. 두 값을 같게 주면 고정됩니다. (예: `--light-scale 2 2`) |
| `--light-seed N` | 같은 조명을 다시 내고 싶을 때, 로그에 찍힌 씨앗 값을 넣습니다. |
| `--no-light-jitter` | 조명을 바꾸지 않고 기본 상태로 고정합니다. |

---

## ⚠️ 한계점 (알아두어야 할 것)

* 1.5% 더 멀게 나오게 만든 것은 임의로 넣은 설정입니다. 실제 로봇이 1–2cm 오차를 내는 원인이 완벽히 똑같은 물리적 현상 때문인지는 확실치 않습니다.
* 여기에 적용된 노이즈나 조명 범위는 임의로 설정한 값이지, 실기에서 잰 값이 아닙니다.
* 일반 시뮬레이션 카메라와 렌즈 화각(fx값 및 중심점)이 아주 미세하게 다릅니다.
* 현재 데모 평가 서버(`demo_server/`)에서는 이 `--zed-depth` 옵션을 지원하지 않습니다.
